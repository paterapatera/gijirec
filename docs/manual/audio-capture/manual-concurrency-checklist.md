## 手順 A — Web 会議アプリ並走（要件 4.1 / Performance/Load 4）

**目的:** gijirec が `capturing` の間、同一マシン上の Web 会議アプリで **持続的な** 相手音声（または映像）の途切れを引き起こさないこと。

**不合格の目安:** 相手音声が断続的に消える・映像が長時間フリーズし、**gijirec のキャプチャを停止（またはアプリ終了）すると改善する**。一時的なネットワークジッタは許容。

### 共通準備

1. Windows 10/11 または macOS 13+ の実機。
2. gijirec を release または dev ビルドで起動: `cargo tauri dev --manifest-path src-tauri/Cargo.toml`（または配布 `.app` / `.exe`）。
3. マイク・システム音声権限を許可し、UI が **`capturing`** であることを確認。
4. ヘッドフォン使用を推奨（スピーカー出力とループバックの混線を避ける）。

### A-1. Zoom

1. **Zoom Workplace**（デスクトップクライアント）をインストール・起動。
2. テスト用ミーティングに参加（2 端末以上、または Zoom のテストミーティング / 信頼できる相手）。
3. 相手側で **連続した音声**（会話、音楽、テストトーン）を **10 分以上** 流す。
4. 自端末で以下を確認:
   - 相手音声に **持続的な途切れ** がない（数秒以上の無音が繰り返される等）。
   - 任意: 相手映像の lip sync / 画面共有に **gijirec 停止で改善する** 長時間フリーズがない。
5. **対照:** gijirec を `stop` またはウィンドウ閉鎖後、同条件で再度 5 分聞き、途切れが gijirec 起因だったか切り分ける。

### A-2. Microsoft Teams

1. **Microsoft Teams**（デスクトップクライアント）をインストール・起動。
2. A-1 と同様にミーティング参加・10 分以上の相手音声確認。
3. 合格基準は A-1 と同じ（持続途切れなし、停止後改善型の途切れは不合格）。

### 動画同期の補助（任意）

- 相手が **口パクまたは秒針付き動画** を共有している場合、音声と映像の **目に見えるずれの急拡大** や **フレーム停止の持続** をメモする。
- 自動同期ハーネスは未導入 — 主観 + メモで足りる。

## 手順 B — ウィンドウ閉鎖とマイクインジケータ（要件 3.2 / E2E/UI 3）

**目的:** ユーザーが gijirec ウィンドウを閉じた後、音声取得が停止し、OS のマイク使用中インジケータが消えること。

1. gijirec を起動し **`capturing`** まで進める。
2. OS のマイク使用中表示を確認:
   - **Windows:** タスクバー / システムトレイのマイクアイコン（使用中状態）。
   - **macOS:** メニューバーの **オレンジ / 黄色のマイク指示**（Monterey 以降のプライバシー表示）。
3. gijirec の **メインウィンドウを閉じる**（× ボタン。可能なら通常終了パス）。
4. **10 秒以内** を目安に確認:
   - gijirec プロセスが終了している（タスクマネージャ / Activity Monitor に `gijirec` が残っていない）。
   - マイク使用中インジケータが **消灯** している。
5. 不合格例: ウィンドウ閉鎖後もインジケータが点灯したまま、または gijirec プロセスが残存。
