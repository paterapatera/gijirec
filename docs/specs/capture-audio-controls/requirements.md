# 要件定義書

## はじめに

会議利用者は、相手の発話のみを文字起こししたい場面でマイク入力を止められず、推論に渡る音声レベルも内部の固定ゲインに依存している。gijirec は、キャプチャ設定 UI 上でマイクの ON/OFF、転写 ingest 直前の音量レベル（dBFS）表示、手動ゲイン調整を提供し、ユーザーが −18〜−17 dBFS 付近に目視で合わせられるようにする。

## スコープ境界

- **対象範囲**: マイク入力の ON/OFF（OFF 時はスピーカー／システム音声のみを転写パイプラインへ供給）、転写 ingest 直前の音量レベルの dBFS 表示、手動ゲイン調整 UI、既存のデバイス選択パネルおよびキャプチャ再開フローとの整合
- **対象外**: OS 側のデバイス音量・システムミキサーの代替、OS レベルのマイクミュートや他アプリへのマイク入力遮断（本 feature は転写 ingest ミックスからのマイク除外のみ）、自動 AGC の新設、仮想オーディオデバイス導入、録音ファイルへのエクスポート、話者分離、生 PCM のフロントエンド配信
- **信頼境界・データ取扱い**: ローカル単一ユーザー運用のため追加認証は不要。フロントへ配信するのは dBFS 等のレベル表示用メタデータのみとし、生 PCM は転送しない（要件 2）。マイクトグル・手動ゲインは既存キャプチャ／デバイス選択と同一 IPC 信頼境界内で扱う
- **隣接システム・仕様への期待**: `audio-device-selection` によるマイク／スピーカー選択とキャプチャ再開は継続利用する。`transcribe-volume-normalize` で実装済みの ingest 固定ゲイン（×1.25 + ソフトリミット 0.95）は、手動ゲイン調整の基準点として置き換えまたは上書き可能とする（詳細は設計で決定）。キャプチャ段の自動ミキサー正規化（−20 dBFS 目標）は本 feature の直接制御対象外とする

## 要件

### 要件 1: マイク入力の ON/OFF

**目的:** 会議利用者として、マイク入力を OFF にしてスピーカー（システム音声）のみを文字起こししたい。その結果、自分の発話を拾わず相手の音声だけを転写できる。

#### 受け入れ条件

1. gijirec は、セッション中にマイク入力を ON/OFF できるユーザー操作を提供すること。
2. マイク入力が OFF のとき、gijirec はスピーカー／システム音声のみを転写 ingest パスへ供給すること。
3. マイク入力が ON のとき、gijirec は既存の二重キャプチャ動作と整合する形で、マイクとスピーカー／システム音声のミックスを転写 ingest パスへ供給すること。
4. キャプチャが有効な状態でユーザーがマイクを ON/OFF したとき、gijirec はアプリの再起動を要求せずに新しい状態を反映すること。
5. マイク OFF の適用により転写に利用可能な音声源がなくなる場合、gijirec は既存のキャプチャエラー表示と同様の形式で、日本語の案内（`message_ja` / `action_ja`）をユーザーに表示すること。
6. 転写へ音声を供給していないキャプチャ状態の間、gijirec はマイクトグル操作を無効化するか利用不可であることを明示し、非キャプチャ時の既存デバイス選択 UI の挙動と整合させること。

### 要件 2: 転写 ingest 直前の音量レベル表示

**目的:** 会議利用者として、文字起こしに渡る直前の音声レベルを dBFS で確認したい。その結果、環境や会議アプリの音量差を目視で把握できる。

#### 受け入れ条件

1. gijirec は、転写 ingest 直前の信号の音量レベルを dBFS で表示すること。
2. キャプチャが転写 ingest へ音声を供給している間、gijirec は表示中の dBFS レベルを少なくとも 1 秒に 1 回更新し、会議中のレベル変化をユーザーが確認できるようにすること。
3. gijirec は、表示レベルが dBFS（任意の単位ではない）であることをユーザーが識別できるラベルまたは表示形式を用いること。
4. 転写 ingest へ利用可能な音声が供給されていないとき、gijirec は誤解を招く固定レベルを表示せず、レベルメーターが非活性または利用不可であることを示すこと。
5. gijirec は、レベルメーター表示の目的のみで生 PCM 音声をフロントエンドへ配信しないこと。

### 要件 3: 手動ゲイン調整

**目的:** 会議利用者として、転写 ingest 直前の音量を手動で調整したい。その結果、推論窓の目標レベル（−18〜−17 dBFS）付近にユーザーが合わせられる。

#### 受け入れ条件

1. gijirec は、転写 ingest 直前に適用する手動ゲインを調整できるユーザー操作を提供すること。
2. ユーザーが手動ゲインを変更したとき、gijirec はアプリの再起動を要求せず、以降に ingest される音声へ新しいゲインを適用すること。
3. 手動ゲインが調整可能な間、gijirec は表示中の dBFS レベル（要件 2）をゲイン調整後の ingest 直前信号と整合させ、ユーザーが −18〜−17 dBFS 付近へ合わせられるようにすること。
4. gijirec は、転写品質またはシステム安定性を著しく損なう持続的なクリッピングや過大増幅を防ぐよう手動ゲインを制約し、上限または下限に達した場合はユーザーにフィードバックを表示すること。
5. キャプチャが転写 ingest へ音声を供給していないとき、gijirec は手動ゲイン操作を無効化するか利用不可であることを明示し、非キャプチャ時の既存設定 UI の挙動と整合させること。
6. セッション中にユーザーが手動ゲインを変更していないとき、gijirec は `transcribe-volume-normalize` の現行固定 ingest ゲイン（×1.25、ソフトリミット 0.95）と等価な ingest 直前ゲインを適用し、既存の転写音量を変えないこと。

### 要件 4: 既存 UI・キャプチャフローとの整合

**目的:** 会議利用者として、デバイス選択やキャプチャ状態と矛盾しない操作体験を維持したい。その結果、新機能を既存の会議フローに自然に組み込める。

#### 受け入れ条件

1. gijirec は、マイクトグル、dBFS レベル表示、手動ゲイン操作を、既存のデバイス選択パネルと同一のキャプチャ設定領域に配置すること。
2. キャプチャが有効な状態でユーザーがマイクまたはスピーカーのデバイス選択を変更したとき、gijirec はユーザーに表示されるエラーにより継続できない場合を除き、キャプチャ再開をまたいでマイク ON/OFF 状態と手動ゲイン設定を保持すること。
3. キャプチャがエラー状態に入ったとき、gijirec はキャプチャ音声制御 UI を既存のキャプチャエラー表示（日本語メッセージと復旧案内）と整合する形で提示すること。
4. gijirec は、マイクトグル、レベル表示、手動ゲインの利用に仮想オーディオデバイスや OS ミキサー変更を要求しないこと。
5. gijirec は、キャプチャ設定領域の縦方向の占有を最小化するため、マイクトグル・dBFS レベル表示・手動ゲイン操作および既存のデバイス選択項目を、可能な範囲で横並びに配置し、転写エディタの入力領域を不必要に狭めないこと。

### 要件 5: パフォーマンスと安定性

**目的:** 会議利用者として、音量メーターとゲイン調整を使っても会議中のアプリ動作が著しく重くならないようにしたい。その結果、文字起こしと編集を継続できる。

#### 受け入れ条件

1. キャプチャが有効な間、gijirec はレベルメーターまたはゲイン調整が原因となる持続的なバックプレッシャーやドロップアウトを発生させず、転写 ingest への音声供給を継続すること。
2. gijirec は、レベル表示の更新およびゲイン調整の適用により、既存のステータス UI が既に示す範囲を超える転写エディタ領域の目に見えるレイアウトシフトや点滅を発生させないこと。
3. リソース圧迫下でレベルメーターまたはゲイン調整を維持できない場合、gijirec は転写を無言で停止せず、メーター更新の低速化などにより段階的に性能を低下させること。
