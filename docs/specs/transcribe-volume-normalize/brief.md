# Brief: transcribe-volume-normalize

## Trigger
Whisper 転写の動作確認で、OS 音量を上げると（例：スライダー 30→50、約 +4.4 dB）転写精度が明確に向上する事象を確認。実測では精度向上時の推論窓 RMS は約 **-18.7 dBFS** であり、現行ミキサー目標 **-20 dBFS**（`TARGET_RMS = 0.1`）より約 +1〜2 dB 大きい。

## Problem
人間に快適な OS / 再生音量と、Whisper が精度よく認識できる入力レベルが一致しない。快適音量（機材により 30〜80 とバラつく）では推論窓 RMS が約 **-23 dBFS** となり小さすぎる可能性が高く、OS 音量に依存した運用は要件にできない。

## Desired Outcome
ユーザーが OS 音量を上げなくても、Whisper 入力が安定して認識できるレベル（推論窓 RMS **-18〜-17 dBFS** 付近）に正規化される。モニター出力など人間の聴感には影響しない。機材差（マイク・スピーカー・ループバック）をソフト側で吸収する。

## Scope
- **In**:
  - 転写パス限定のゲイン／正規化（ミキサー出力または Whisper 直前）
  - 目標入力レベル：推論窓 RMS 約 **-18〜-17 dBFS**（初期ゲイン ×1.4〜1.5 または転写専用 `TARGET_RMS` 0.12〜0.13）
  - ソフトリミッター（現状 0.95）によるクリッピング防止
  - 静かな入力でもゲイン上限内で目標に近づける（`MAX_GAIN` 見直し含む）
  - 既存 RMS ログ（`transcribe_window_rms_dbfs` 等）での効果検証
  - v1 は固定値（設定 UI 不要）
- **Out**:
  - OS / デバイス音量の自動制御
  - モニター出力の快適音量調整
  - AGC / コンプレッサの本格導入
  - ユーザー向け「転写感度」スライダー UI

## Route
- **Path**: C
- **Rationale**: 既存 spec はアーカイブ済みで単一の新機能境界として独立しており、転写専用レベル正規化という一つのスコープに収まる。

## Approach
優先：転写パス専用ゲイン（デフォルト **×1.45** 前後）を `pcm_ingest` または推論直前に適用。代替（二番手）：`TARGET_RMS` を `0.12` に変更（全経路に影響するため）。

## Current State
実装基盤は完了済み `audio-capture`（ミキサー `mixer.rs`：トラック別 RMS 正規化、目標 -20 dBFS、`MAX_GAIN = 4.0`）と `whisper-transcribe`（`transcribe_worker.rs`：30 秒固定バッチ窓、無音スキップ閾値 0.008）。Whisper アダプタに追加前処理なし。RMS ログは実装済み。

## Constraints
- PCM 生データ・転写本文をログに出さない（現行契約維持）
- 既存キャプチャ／ミキサー契約を破らない
- ピークが -12 dBFS 前後のため過大ゲイン禁止
