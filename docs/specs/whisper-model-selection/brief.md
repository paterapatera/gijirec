# Brief: whisper-model-selection

## Trigger
Whisper 転写で、用途やマシン性能に応じてモデルサイズを選びたいという要望。**kotoba-whisper-v2.2** の **Q5_0 / Q8_0 / FP16** の 3 段階で切り替えたい。

## Problem
モデル（量子化レベル）をユーザーが選べないため、精度・速度・メモリのトレードオフを状況に合わせて調整できない。軽い Q5_0 で速く回したい場面と、FP16 で精度を優先したい場面で同じ設定に縛られる。

## Desired Outcome
ユーザーが **kotoba-whisper-v2.2** の **Q5_0 / Q8_0 / FP16** から選び、選択が転写に反映される。未ダウンロードのバリアントは取得後に利用できる。選択はセッション間で保持される。

## Scope
- **In**:
  - kotoba-whisper-v2.2 の 3 バリアント（**Q5_0 / Q8_0 / FP16**）の選択 UI または設定
  - 選択に応じたモデル取得・ロード・転写への適用
  - 切り替え時の状態表示（取得中・準備完了・エラー等、既存 transcribe フェーズと整合）
  - 選択の永続化（設定ストア等）
- **Out**:
  - kotoba-whisper 以外のモデルファミリ
  - カスタム／ファインチューンモデル
  - クラウド STT
  - ハードウェア自動推奨（v1）
  - 上記 3 バリアント以外の量子化（例: Q4_0）
  - 転写中のホットスワップ（v1 は切り替え後の次回推論から反映でも可）

## Route
- **Path**: C
- **Rationale**: 完了済み `whisper-transcribe` の拡張だが spec はアーカイブ済み。モデルバリアント切り替えは単一の新 spec 境界に収まる。

## Approach
設定で kotoba-whisper-v2.2 のバリアント（Q5_0 / Q8_0 / FP16）を選び、バックエンドのモデル取得・ロード経路をバインドする。具体的な ggml ファイル名・切り替えタイミングは要求フェーズで既存実装を踏まえて定義。

## Current State
`whisper-transcribe`（完了・アーカイブ）でローカル推論・モデル取得・フェーズ／進捗 UI あり。`transcribe-volume-normalize` は別 spec（音量正規化）で依存なし。

## Constraints
- モデル初回取得後のオフライン運用を維持
- 既存 transcribe IPC／イベント契約との後方互換
